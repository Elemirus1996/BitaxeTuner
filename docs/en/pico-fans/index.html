BitaxeTuner server · accessories

Pico fan controller

A Raspberry Pi Pico 2 on the Pi 3's USB port controls up to six 4-pin PWM fans: one for the voltage regulator (VR) of each Bitaxe and up to three for the case. On top come a 7.5-inch e-paper with the most important values, four buttons and temperature sensors. If anything fails, the fans run at full speed.

Pi 3Ready-made image: write it once, done

The release page has BitaxeTuner-Server-<version>-pi-arm64.img.xz: the official Raspberry Pi OS Lite (64-bit) with the BitaxeTuner server pre-installed, the restart function for button 4 and the host name bitaxetuner. Your credentials and miner data are not part of the image; the desktop app puts them on the SD card afterwards.

  1. Open Raspberry Pi Imager → device “Raspberry Pi 3” → operating system “Use custom” → the .img.xz file → SD card (16 GB or more) → write. The Imager offers no settings for custom images – the app takes care of that in the next step.
  2. Re-insert the SD card. In the BitaxeTuner app (0.3.1 or later): Mode → Prepare Raspberry Pi → choose the “bootfs” drive, enter the admin password for the server twice, user and password for the Pi (SSH), Wi-Fi name and password (Pi 3: 2.4 GHz only; empty = LAN cable only), tick “Include my data” → “Write setup package to the SD card”. All passwords are stored on the card only as hashes. The app remembers the address and access token.
  3. Insert the card into the Pi and power it on. The first boot takes 3–5 minutes (expand the file system, create the user, apply the package). Afterwards the Pi deletes the password hash and the data copy from the card.
  4. In the app: “Test connection” → “Switch only”. Only now does the Pi poll the miners, and the PC stops doing so. The interface is also available in the browser at http://bitaxetuner.local:8484/.
Without a setup package the server starts empty; then set it up in the browser. Get the setup code with ssh <user>@bitaxetuner.local and sudo cat /var/lib/bitaxetuner/SETUP-CODE.txt. If the PC doesn't find bitaxetuner.local, enter the Pi's IP address from your router. First-boot log: /var/log/bitaxetuner-firstboot.log.
Backup to a USB stick (version 0.4.0 or later): plug a stick (FAT32, exFAT or ext4) into the Pi and choose “Use a USB stick on the Pi” in the browser under Settings → Backup. The Pi then backs up to the stick every day. On a Pi that was set up before 0.4.0, run this once via SSH after the server update: sudo sh /opt/bitaxetuner/current/install.sh --system.

Each PWM pin sits on its own PWM slice of the Pico, so every channel gets a clean 25 kHz. Which channel belongs to which miner is set later in the interface; the table is only the suggested wiring. If you only build Ch1–Ch3 for now, Ch4–Ch6 simply stay empty.

Everything goes on an 830-point breadboard (columns 1–63, rows a–j). The drawing shows channel Ch1 fully wired; Ch2–Ch6 are built the same way, each six columns further right. On the breadboard R3 is left out: the software switches on the Pico's built-in pull-up for the tach line.

Once for all channels

  • Pico GND: jumper a3 → upper blue rail.
  • Power via the USB fan adapter on a USB charger (5 V, at least 2 A): two female-male jumpers, socket onto the adapter pins, pin into the board. Pin 2 (+5 V, red/yellow) → upper red rail, pin 1 (GND, black) → upper blue rail. Pins 3 and 4 stay free.
  • Ground jumper: upper blue rail → lower blue rail (e.g. at column 62).
  • Electrolytic capacitor 470 µF: long leg (+) into the upper red rail, striped leg (−) into the upper blue rail.
Before powering on for the first time: 0. Measure between pin 1 and pin 2 of the USB fan adapter: it must be about 5 V. Some adapters step up to 12 V (labelled “12V” or with a small box in the cable) – that would destroy the 5 V fans. 1. Don't plug anything into column 1 at the top (a1, b1); that's where the 5 V from USB (VBUS) is. 2. On many breadboards the rails are split in the middle (gap in the red/blue line); in that case bridge each rail there with a short jumper. 3. Only plug in fan connectors with the USB charger unplugged; the black wire (pin 1) goes into hole a(B).

E-paper 7.5" (red/black/white)

The module is actually designed for plugging the Pico on top. Here the Pico stays on the breadboard, and only eight wires go via male-male jumpers into the module's socket header – each into the hole where the module expects the signal (column “Target”, pin 1 is marked on the module). Do not plug the Pico directly onto the module: the module expects the display on GP8–GP13, but the fans use GP8 and GP10 here – BitaxeTuner drives the display on GP11–GP15 and GP22. The display's ribbon cable goes into the module's flip-lock connector, contacts facing down.

The display refreshes at most every 3 minutes (default 5, optionally not at all at night) and takes about 16 seconds to do so. That protects the panel. On an alert (miner offline, case too warm) it refreshes immediately.

Pages (each can be switched on or off, preview in the browser under Fans & display): overview, daily summary, history, BTC, BCH or both prices, monthly and daily summary with a selectable chart, groups, electricity price traffic light, temperature sensors and a QR code to the web UI. Colours can be inverted (white text on black). The block found screen ends either after a configurable number of hours or – like the warnings – only with button 1.

Program updates: when a new BitaxeTuner version ships a new fan program, the server installs it by itself on the next connection – via USB or over Wi-Fi – and the Pico restarts. Only MicroPython itself is updated by hand (UF2 file, as during the first setup).

Buttons

The push buttons have solder tabs: one alligator clip each on tab A and B, the other ends on the pins of two male-male jumpers that go into the board. Direction doesn't matter. The Pico has built-in pull-ups, no resistors needed; its LED blinks on every press.

Button 1 flips to the next page or acknowledges a special screen (e.g. block found); the display then reacts after about 30 seconds instead of 3 minutes. Button 2 (automatic) cancels “100 %” and “Off”. Button 3 briefly sets the fans to 100 % immediately, even if the server isn't responding right now; holding it for 5 seconds switches the extra fans off (safety rules stay active). Button 4 only reacts after holding it for 3 seconds (LED lights for 1 s); a short press does nothing. Before restarting, the server stops running benchmarks and restores the miner settings. The buttons can be disabled in the settings.

Several temperature sensors (e.g. power supply and miner room)

The 3-wire DS18B20 all hang in parallel on the same three lines: column 60 collects 3.3 V, column 61 the data (both columns are free to the right of Ch6). There is only one 4.7 kΩ resistor, no matter how many sensors. Each sensor has a fixed built-in ID: the server recognises it by that and adds it by itself under “Fans & display → Temperature sensors”, where you give it a name and a warning threshold.

  • Which one is which? Warm a sensor in your hand and watch which value rises in the list.
  • Red must be connected (no “parasitic” mode over 2 wires).
  • Soft stranded wire ends hold poorly in a breadboard: use an alligator clip onto a male-male jumper, or ferrules or Dupont connectors.
  • Sensor on a small board with its own resistor (often called a “module”, pins −/+/S): then our 4.7 kΩ is not needed; three such modules are still fine.
  • Cables up to about 10 m in total are no problem with 4.7 kΩ.

For each sensor you decide whether it counts for the case fans (measured value “Temperature sensors”, the warmest one applies) and whether it appears on the display. Too warm → push notification and red display line. Sensor missing for more than 2 minutes → notification. If it counts for the case fans, they run at the value for “unknown” (default 100 %) until then.

+5 V to all fan pins 2, ground to the GND rail. An electrolytic capacitor (470 µF) on the 5 V rail smooths voltage spikes at start-up.

12 V case fans (if you have them)

The circuit is the same: the PWM signal doesn't depend on the fan voltage. Pin 2 then gets +12 V from a second power supply whose minus also goes to the common GND rail.

+12 V must never touch the Pico, the Pi or the 5 V line. Separate screw terminals and coloured wires help.

Don't power the fans from the Pi's 5 V pin or the Pico's USB: the Pi 3 has little headroom for that, and fans briefly draw much more current when starting up.

AssemblyPutting it together and first test

  1. MicroPython onto the Pico: hold the BOOTSEL button, plug the Pico into a PC via USB, drag the UF2 file for “Raspberry Pi Pico 2” (RPI_PICO2) from micropython.org/download onto the drive that appears. The server flashes the fan program itself later.
  2. Populate the breadboard according to the layout – first the Pico, rails and ground jumper, then one channel after the other. Don't connect any fan or power supply yet.
  3. Check (multimeter, continuity test): no continuity between the red and the blue rail; nothing in column 1 at the top (VBUS); every black fan wire ends up in a(B).
  4. First the USB charger, then one fan on Ch1: without the Pico it must run at full speed right away. That's the fail-safe, which works here even without software.
  5. Plug the Pico into the Pi 3 via USB. The server detects it, uploads the fan program and takes over control; the speed appears in the interface.
  6. Assign the fans (Fans & display) and connect the remaining channels.
  7. Good to know: from fan program v8 a hardware watchdog supervises the Pico. If its program hangs, it restarts after 8 seconds, and until then the fans run at full speed. If you open the Pico with Thonny or a terminal for tinkering, you will therefore see a restart every few seconds – for tinkering, flash MicroPython again first (BOOTSEL + UF2); the server installs the fan program again afterwards.

From 0.9.7No cable to the server: Pico via WLAN

With a Raspberry Pi Pico 2 WH (with WLAN, headers already soldered) the fan controller and the display no longer have to be connected to the server via USB. There are two variants, which can also be combined:

Fan Pico

Pico 2 WH instead of Pico 2 H on the fan board (or the breadboard) – same form factor, same pins. The fans still get their power from the board's USB-C socket, the Pico gets its own USB power supply on its micro-USB socket.

An e-paper can still hang on the board via cable.

Display Pico

Plug the Pico 2 WH directly onto the Waveshare e-paper module – no wires, no board. Orientation as shown by the Pico outline printed on the module (USB socket on the marked side), with power off. Power via a USB power supply on the Pico.

It shows the display and reports its buttons; it has no fans. For this the program uses the Waveshare pin layout (GP8–GP13).

  1. Install MicroPython for the W: hold BOOTSEL, connect the Pico to a PC via USB, drag the UF2 file for “Raspberry Pi Pico 2 W” (RPI_PICO2_W) from micropython.org/download onto the drive. The file without “W” has no WLAN.
  2. Connect the Pico to the server with a USB data cable (Pi or PC running the BitaxeTuner server). If another Pico is already plugged in there, choose the right port in the dialog.
  3. In the browser open Fans & display and choose “Set up fan Pico for WLAN …” (card Connection) or “Set up display Pico for WLAN …” (card E-paper display, “Display is attached: own display Pico”).
  4. Enter WLAN name and password (the Pico only supports 2.4 GHz), keep or change the device name. After about 30 seconds BitaxeTuner reports “Set up” and the IP address the Pico got.
  5. Unplug the Pico from the server and connect it to its own power supply (5 V, 1 A is enough). The server connects by itself within a few seconds; the connection is shown under Connection or “Connected via”.
Good to know: The server looks for the Pico as bitaxetuner-fans.local or bitaxetuner-display.local and otherwise falls back to the last IP address it reached. Most reliable is a fixed IP in the router (DHCP reservation) – then enter it in the field “WLAN: device name or IP address”. New versions of the Pico program are installed by the server over WLAN, no cable needed.

Security

  • During setup every Pico gets its own random key. Both sides prove it when connecting, after that every line is signed and numbered – other devices on the WLAN can neither switch fans nor inject values or replay old commands.
  • The WLAN password is stored only on the Pico, not on the server. Whoever gets hold of the Pico can read it, though – so don't leave the Pico lying around openly.
  • The fail-safe stays: if the WLAN drops, the fan Pico gets no more commands and sets all fans to 100 % after 5 seconds. Button 3 sets 100 % even without server.
  • After 10 minutes without server the e-paper shows “KEINE VERBINDUNG ZUM SERVER” (no connection to server).

If it doesn't work

“key does not match”
The Pico was set up again elsewhere or the server was reinstalled → set the Pico up for WLAN again via USB.
“does not answer (WLAN?)”
Check WLAN name/password, is the 2.4 GHz network on? Look up the Pico's IP in the router and enter it.
“is set up as display Pico”
Fan and display Pico swapped → use the other setup button.
Display stays blank
Fixed from fan program 7.1 (before, the Pico's SPI took the display's DC line, GP8). To check the hardware without a server: open epd_test.py in Thonny and "Run" – after 20–30 s a test picture with a black and a red bar appears. The program on the Pico stays unchanged.
Back to USB
Choose “Connection: USB cable on the server” and save; the program keeps working via USB.

Always active, cannot be switched off

  • Miner offline or its data older than 30 seconds → its fan to 100 %.
  • Pico receives no command for 5 seconds (server hangs or restarts) → all fans to 100 %.
  • Pico without power or USB unplugged → the circuit itself ensures 100 %.
  • Fan should spin but reports 0 rpm → push notification “fan stalled”.
